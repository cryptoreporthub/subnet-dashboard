  `soul_path` to `_last_resolver_tick`. Only one test passes it, to assert the compat contract. The source of
  truth is the process-wide `LivenessTracker` registry, so a process-wide TTL cache is legitimate in
  production. The defect is that tests share one process. The reset fixture is the same isolation pattern as
  the readiness-cache and rate-limiter fixtures. The unused `soul_path` parameter is dead and misleading. It is
  left in place because a test pins it. Removing it is a separate small cleanup.
- Why main's full run did not show it is a guess. With a 5 second window the leak needs the victim to run
  within seconds of the polluter, so any change in what runs between them can hide it.
- `test_resolver_revive.py::test_revive_recycles_hung_scheduler_and_runs_once` fails alone, on main and on the

- Not verified: that no failure is hidden by the 145 pre-existing ones. The comparison is by test id, so a

### The two failures new to the eleven-branch run

Both fail on clean `ef234c95` when run alone. Neither is caused by a branch (bisect, measured).

- `test_ops_readiness.py::test_readiness_pump_desk_trust_not_ready_when_stale`. Cause (measured). The
  liveness registry merges the persisted `liveness` bucket of `data/soul_map.json` and prefers it when its
  freshness string sorts later than the in-process tracker's. Earlier tests leak `pump_ladder` failure state
  (`tick_body_stalled`) into that file, so the assertion races it. `data/soul_map.json` is gitignored
  (`.gitignore:49`), so `git checkout -- data` does not restore it and every checkout carries its own copy.
  That is why the result depends on the checkout. Change: the test now points `SOUL_MAP_PATH` at a `tmp_path`
  file (commit `adf9c5a4` on `claude/test-rate-limit-isolation`). This makes the victim hermetic. It does not
  remove the polluter. The test that writes `pump_ladder` failure state into the real soul map is not
  identified and is open (section 5). Passes alone and in its file. The file's two other failures,
  `test_ops_readiness_contract` and `test_probe_feed_layers_uses_worker_on_split_v2_web`, are on main's failed
  list and unchanged. The full run after this change is in the final-run subsection below.
- `test_phase_h_ui.py::test_h_full_daily_pick_hero_or_honest_empty`. Cause (measured by `git log -S`). The
  test asserted `council-call`, which K3-1 (`5bd1e38c`) removed from `council_stage.html`. The hero states its
  stance through `k3-action-badge` with a SEALED, GATED, FORMING or COLD label
  (`internal/preview/tribunal_hero.py:68`). The test also relied on an earlier test warming the process-wide
  `_HOMEPAGE_HTML_CACHE`, since a cold `GET /` serves a ~1 KB shell. Fix: warm the cache in the test and assert
  the badge label (commit `74cf48e4` on `claude/fix-phase-h-hero-stance-test`, from `origin/main`). Negative
  control, measured: the old test fails alone and the new one passes alone. The whole file has 11 failures
  before and after, identical by id, and the target passes in the file run either way. The file's 11 failures
  are probably the same cold-cache dependence, but that is inferred, not measured. They are open under
  item 6.
